# 14. 상세페이지 생성 규칙 (Gate B)

상태: `Approved (DEC-010, Claude 세션 결정 2026-11-03, DEC-008 위임)`. 변경은 Gate B 대상이다.

생성 엔진(TASK-007)의 Prompt, 결과 Schema, 후처리는 이 문서를 기준으로 한다.

## 1. 입력

- 내 상품 정보: 이름(필수), 특징 1 ~ 10개(필수), 타깃, 가격대
- 내 사진 목록: 순번과 사용자가 적은 설명(사진 파일은 서버로 보내지 않음, DEC-007)
- 참고 리포트(선택): 경쟁 상세페이지 분석 결과의 `sections`(역할 / 전개 방식 / 소구 포인트 / 이미지 종류), `tone`, `target`

## 2. 섹션 구성

- 참고 리포트가 있으면 그 **역할 순서와 전개 방식**을 따른다. 내 상품 정보로 채울 수 없는 역할(예: 근거 자료가 없는 `proof`)은 빼거나 "준비 필요" 안내로 둔다.
- 참고 리포트가 없으면 기본 순서: `hook` → `problem` → `solution` → `differentiator` → `spec` → `usage` → `shipping` → `cta`
- 섹션 수 5 ~ 10개.

## 3. 템플릿 (`template`)

| key | 용도 | 구성 |
|---|---|---|
| `hero` | 첫 화면(hook) | 큰 제목 + 부제 + 대표 사진 |
| `image-text` | 문제 / 해결 / 사용 장면 | 사진 + 제목 + 본문 |
| `feature-list` | 차별점 / 해결 기능 | 제목 + 항목 3 ~ 5개(bullets) |
| `spec-table` | 스펙 / 구성 | 제목 + "항목: 값" 형식 bullets |
| `notice` | 배송 · 교환 / 주의사항 | 제목 + 짧은 안내 bullets |
| `cta` | 구매 유도 | 혜택 재강조 제목 + 한 줄 + 사진(선택) |

## 4. 문구 규칙

- 한국어, 모바일 기준 한 줄 20자 안팎의 짧은 문장. `headline` 25자 이하, `body` 120자 이하, `bullets` 각 40자 이하.
- 내 상품 정보에 없는 사실(수치, 인증, 수상, 판매량, 성분 효능)을 만들지 않는다. 필요하면 `[확인 필요: ...]` 자리 표시로 남긴다.
- "최고 / 최초 / 1위 / 100% / 완벽" 같은 최상급 · 단정 표현과 질병 치료 · 의학적 효능 표현을 쓰지 않는다(표시 · 광고 관련 법령 위험).
- 참고 리포트의 **구조 / 전개 방식 / 소구 전략만** 참고하고 경쟁 문구를 옮기지 않는다(DEC-007).

## 5. 경쟁 문구 유사도 검사

- 비교 대상: 참고 리포트 `sections[].keyCopy`의 모든 문구.
- 정규화: 공백 / 문장부호 제거, 영문 소문자화.
- 생성 문구(headline / body / bullets)와 비교 대상 사이에 **연속 12자 이상 같은 구간**이 있으면 위반이다. 단, 그 구간이 내 상품 정보(이름 / 특징)에도 그대로 있으면 위반이 아니다(내 상품의 고유 정보).
- 위반 시 위반 구간을 알려 주며 1회 재생성한다. 재생성 후에도 위반이면 결과를 반환하되 `warnings`에 해당 섹션과 구간을 넣어 화면에서 수정하도록 안내한다.

## 6. 사진 배치

- 각 섹션의 `imageGuide`에 어울리는 사진 설명을 쓴다.
- 내 사진 설명과 맞는 사진이 있으면 `imageSlot`에 그 순번을, 없으면 `null`. 같은 사진은 최대 2개 섹션에서 쓴다.
- `hero` 섹션은 사진이 1장 이상이면 반드시 `imageSlot`을 채운다.
